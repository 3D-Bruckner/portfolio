# upload — the portfolio app — Implementation Plan (2 of 4)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Next.js app, `3D-Bruckner/upload`, where Marcel creates, edits, orders and publishes 3dbruckner.de's prints and their photos from his phone and over MCP, which exports the published prints for the site build and triggers that build.

**Architecture:** One Next.js app in one image (pages, `/api/v1`, `/mcp`) over a framework-free `backend/`, SQLite through `better-sqlite3` + `kysely`, photos as JPEG files in `DATA_DIR/photos/`. Sign-in, API tokens, MCP endpoint and OAuth, REST route table and migrations runner come from **`next-app-kit`** (plan 1, `Marceltov/next-app-kit`, tag `v0.1.0`); the project files (lint, Dockerfile, CI with the image job, multipart upload) are taken from noticebox as a starting point; the portfolio domain is new.

**Tech Stack:** next-app-kit v0.1.0 (and its peer versions), Next.js 16.4.6, React 19.3.1, Better Auth 1.7.21 (+ `@better-auth/api-key`, `@better-auth/mcp`, `@better-auth/oauth-provider`, `@better-auth/cimd`, passkey plugin of the same version), `@modelcontextprotocol/server` 2.4.0, better-sqlite3 13.0.3, kysely 0.29.8, zod 4, busboy 1.6.0, nodemailer, **sharp** (photo processing), Tailwind 4, lucide-react, Vitest 5, Playwright 1.64.1. Exact versions as in noticebox's `package.json`.

**Spec:** `docs/superpowers/specs/2026-11-19-portfolio-app-design.md` (this repository).

**The other plans:** 1 — `next-app-kit` (before this one). Written after this one lands, each against this app's export: 3 — the site reads the export (`3D-Bruckner/3dbruckner`: fetch script, `printed.ts`, `pages.yml`, app-triggered builds skip the order-form test, `modellierung.astro` copes with a missing print); 4 — deployment and migration (`3D-Bruckner/stacks`, business ansible: products-1 checkout, Caddy route, DNS, backups, Uptime Kuma; the import of the 25 prints; removing `src/assets/printed/`).

## Global Constraints

- Work on the development box (CT 116 `development`, AMR5), in a clone of `3D-Bruckner/upload` (exists, private; this plan is in it). Never on the Beelink.
- Nothing the kit provides is copied into this app; if the app needs something the kit lacks and another app would need it too, it goes into the kit (Marcel, 2026-11-19).
- Env vars: `UPLOAD_*`, plus `PUBLIC_URL`, `DATA_DIR`, `PORT`, `TZ`. Data: `DATA_DIR/upload.sqlite`, `DATA_DIR/auth.sqlite`, `DATA_DIR/photos/<printId>/<photoId>.jpg`.
- Who may sign in: `UPLOAD_ALLOWED_EMAILS`; empty lets nobody in. Sign-in by emailed code/link (`UPLOAD_SMTP_URL`, `UPLOAD_SMTP_FROM`, sender `noreply@3dbruckner.de`) plus passkeys. No authentik in front.
- UI text German; code, logs, MCP descriptions and `guidance` English.
- Every MCP result carries `guidance: string[]` (the kit's `defineTool` enforces it) and the URL of each print it names (`<PUBLIC_URL>/prints/<id>`).
- Photo processing: EXIF orientation applied, long edge capped at **2400 px** (never enlarged), JPEG **quality 85**, **no metadata kept**; the original never touches disk outside the request's temp file, which is deleted.
- Slugs: `toSlug` identical to the site's (`src/lib/printed.ts` in 3dbruckner: lowercase, ä→ae ö→oe ü→ue ß→ss, non `[a-z0-9]` runs → `-`, trimmed). A slug is fixed once a print was first published and is never reused after delete.
- Site build trigger: quiet period **60 s** after the last site-visible change, then `POST https://api.github.com/repos/3D-Bruckner/3dbruckner/actions/workflows/pages.yml/dispatches` with `{"ref":"main","inputs":{"source":"upload"}}`, token `UPLOAD_GITHUB_TOKEN` (fine-grained, `actions: write` on that repo only). Only changes to published prints, categories in use, order and showcases are site-visible.

## Review Focus

1. **A phone on mobile data drops mid-upload** → that one photo fails with a German message and can be retried; nothing half-written stays (Task 3 test `abortedUploadLeavesNothing`).
2. **An iPhone sends HEIC** (when a photo is shared, not picked) → refused with "Bitte als JPEG hochladen" instead of a 500; the file input's `accept="image/jpeg,image/png,image/webp"` makes iOS transcode to JPEG (Task 3 test `refusesHeic`, Task 8 e2e checks the attribute).
3. **Two saves in quick succession** (title, then price) → exactly one dispatch after the quiet period; an app restart inside the quiet period still dispatches (Task 6 tests `debouncesBursts`, `pendingSurvivesRestart`).
4. **Publishing a print whose title slugs to a reserved or taken slug** (e.g. a re-created "Beyblade – Dragoon" after delete) → refused with the clash named, never a silent `-2` suffix that would surprise Marcel (Task 2 test `publishRefusesReservedSlug`).
5. **Deleting a category still used by a published print** → refused, naming the prints (Task 2 test `deleteCategoryInUseRefused`).
